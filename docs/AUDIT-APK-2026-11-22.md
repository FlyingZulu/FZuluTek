# Audit ZuluTek APK — 22 novembre 2026

Statut : **corrections proposées sur branche dédiée, non validées par build Android ni matériel**.

## Périmètre inspecté

- Structure Gradle : `settings.gradle`, `app-zulutek/build.gradle`, workflow `.github/workflows/build.yml`.
- Sources : `Fm1Usb.kt`, `ZtfTransport.kt`, aperçu de `MainActivity.kt`.
- Contexte : veille FM-1 (émulateurs Rust/QEMU, FM1-RE, FM1Buddy, FM1 Mirror, Dinghy, ZP12).
- Les autres modules DSP/UI, parcours fonctionnels et la chaîne firmware restent à auditer ; ceci n'est **pas** un certificat d'audit exhaustif.

## Défauts corrigés

### ZT-AUD-001 — événements USB-MIDI mal encodés (critique)
`UsbMidiLink.send` construisait des buffers `4 + take` octets (5 à 7 octets), avec les données copiées à l'offset 4. Le protocole USB-MIDI impose un événement de **4 octets** (en-tête CIN/câble à l'offset 0, données à 1..3). Correction : buffer fixe de 4 octets, copie à l'offset 1, rejet d'une écriture USB partielle.

### ZT-AUD-002 — réassemblage SysEx à mauvais offset (critique)
`UsbMidiLink.readLoop` lisait `p + 4 + k` au lieu de `p + 1 + k` dans chaque événement USB-MIDI. Correction de l'offset. Impact probable : trames SysEx corrompues / absence de réponses ZTF.

### ZT-AUD-003 — transfert ZTF sans progression (important)
`ZtfTransport.fileRead` pouvait boucler si une réponse READ ne contenait aucun octet utile. `fileWrite` pouvait boucler si l'ACK répétait le même offset. Correction : refus des lectures sans progression et des ACK hors bornes ou non progressifs ; garde sur les tailles et offsets de reprise.

## Anomalies ouvertes — à traiter avant livraison

- **ZT-AUD-004 (important)** : `Fm1Usb.ping/pull/push/pushNamed` soumettent une tâche asynchrone mais renvoient immédiatement une valeur par défaut. Rechercher les appelants, puis adopter une API callback / résultat asynchrone ; ne pas convertir en appel bloquant sur le thread UI.
- **ZT-AUD-005 (important)** : vérifier la synchronisation et le cycle de vie USB : `UsbDeviceConnection` n'est pas explicitement fermée dans `UsbMidiLink.close`; scan et reconnexions peuvent laisser des ressources ouvertes.
- **ZT-AUD-006 (à tester)** : comparer les réponses ZTF aux firmwares réels ; les projets externes ne prouvent pas leur compatibilité avec le protocole privé ZTF.
- **ZT-AUD-007 (à tester)** : vérifier le comportement d'une notification compagnon reçue pendant une requête ZTF, et les réponses inattendues dans `zrequest`.
- **ZT-AUD-008 (à tester)** : test de build complet, installation sur Android, rotation paysage, USB permission/débranchement, audio Oboe et interface tactile.

## Validation demandée

1. Exécuter `gradle :app-zulutek:assembleDebug --no-daemon` sur CI.
2. Ajouter tests unitaires des événements USB-MIDI (SysEx de longueurs 1..N, fin CIN 5/6/7, paquets multiples, lecture partielle).
3. Simuler des réponses ZTF READ/DATA malformées ou non progressives ; vérifier l'arrêt avec erreur.
4. Tester sur téléphone Android en mode USB host avec un firmware ZTF connu, après sauvegarde.
5. Ne flasher **aucun** FM-1 sur la base de ce seul audit.

## Décision de livraison

Corrections proposées dans `audit/zulutek-usb-midi-20261122` ; revue et CI nécessaires avant fusion. Aucun changement de design, de protocole ZuluLink, de clé de signature ou de firmware.
